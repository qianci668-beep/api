# Agent2API 保留青溪系统提示词：本地修复记录

日期：2026-10-30（2026-10-31 按旧版逻辑复核修订）

## 修复内容

Agent2API 原实现会在上游返回内容拦截时，将客户端的 system 消息替换为最小中性提示词，并使后续请求进入持续到零点的降级状态。青溪的身份、规则和工具约束都包含在 DSH 传入的 system 消息中，这会导致插件表现失效。

本机修复（已对照旧版备份 `qianci668-beep/api` 逐项复核）：

- `server/src/server/core/upstream/payload.rs`：构造出站请求时不再读取历史降级状态，使用正常提示词配置处理请求。
- `server/src/server/core/upstream/provider_loop.rs`：内容拦截不再触发全局降级，不再换中性提示词进行补救重发；普通对话的内容拦截按普通错误路径收尾（与旧版行为一致）。图片操作的内容拦截提前返回分支为上游原有行为，已恢复。
- `server/src/server/core/sanitize.rs`：**保持上游原有行为**——对所有角色（含 system/developer）统一脱敏。复核结论：青溪 27,423 字符提示词实测命中 0 条脱敏规则（`sensitive_hits=[]`），无需排除；排除反而会破坏对 Claude Code 等客户端 system 指纹的既有防护。2026-10-31 已还原。

青溪本地 RC4 适配版已有完整 system 装配、历史注入及当前提示词保留补丁，未修改其提示词内容。该插件通过 `link:D:/codex/richang/qingxi-source` 加载，源码目录仍需保留。

这保证的是代理不再主动删除或替换客户端 system；不保证上游一定接受请求或模型一定遵循提示词。上游仍可能按自身规则拒绝内容。
